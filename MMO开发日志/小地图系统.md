### 原理

整张小地图其实是一张**整场景俯视图的 Sprite**，挂在 `UIMinimap` 里的 `minimap` 这个 `Image` 上。屏幕上你只看到一个小圆 / 小方框，是因为外面套了个 `Mask`，Mask 相当于一个窗口，只显示窗口里面的那一小块 Image。角色一移动，并不是箭头在大地图上游走，而是大地图那张 Image 在 Mask 背后反方向平移，让“玩家箭头”永远在窗口正中心，看起来就像你在地图上移动一样。代码里就是**每帧改 `minimap.rectTransform.pivot`，然后把 `localPosition` 归零**。

`MinimapBoundingBox` 的作用，就是告诉 UI：这张大地图对应的世界范围到底有多大。
 这个 cube 放在地面下面，不是用来渲染的，只是用它的 `Collider.bounds` 当成“地图真实边界”。`bounds.min` 是地图左下角坐标，`bounds.size.x` / `bounds.size.z` 分别是真实世界里地图的宽和长。这样在 `UIMinimap.Update()` 里，先拿玩家的世界坐标 `(playerTransform.position.x, playerTransform.position.z)`，减去 `bounds.min` 得到一个相对坐标 `relaX / relaY`，再除以 `realWidth / realHeight`  **得到 0~1 的归一化坐标 `pivotX / pivotY`。这个 0~1 的坐标，刚好可以直接塞进 UI Image 的 `pivot`，实现“世界坐标 → 小地图 pivot”的映射**。你完全可以理解为：BoundingBox 提供“原始坐标系和长宽”，UI 做一次**线性插值**把它缩到 [0,1] 区间。

Mask 本身并不会“联动” BoundingBox，它只负责**裁剪**。联动是通过 `UIMinimap` 脚本里的几步完成的：
 每帧先保证 `playerTransform` 和 `minimapBoundingBox` 都有值，然后计算 `relaX / relaY`、`pivotX / pivotY`，更新 `minimap.rectTransform.pivot`，再把 `localPosition` 设为 `Vector2.zero`。由于 Mask 的 Rect 是固定在右下角那块 UI 区域不动的，当 pivot 改变时，Image 实际的纹理采样区域发生偏移，但 RectTransform 位置没变，于是看上去就是“地图在窗子后面移动”。Mask 的存在只是保证你不会看到整张图，只能看到中间那小块。

### 小地图管理

`MinimapManager` 是一个全局单例，用来做**“世界层 → UI 层”的桥**：它知道当前玩家的 `Transform`（通过 `User.Instance.CurrentCharacterObject` 拿），也负责根据当前地图配置加载对应**小地图 Sprite**（`LoadCurrentMinimap()` 调 `Resloader.Load<Sprite>("UI/Minimap/" + CurrentMapData.MiniMap)`）。每个场景里有一个 `MapController`（`MapRoot`下挂载），身上拖了那个地下 cube 的 `Collider` 引用，一进场景的 `Start()` 就把这个 collider 传给 `MinimapManager.UpdateMinimap(minimapBoundingBox)`，顺带触发一下 UI 侧的 `UpdateMap()`，完成“这张地图用这张小地图图、这个 BoundingBox”的绑定。另一方面，UI 那边的 `UIMinimap.Start()` 会把自己注册到 `MinimapManager` 上（`MinimapManager.Instance.minimap = this`），之后每一帧在 `Update()` 里从 `MinimapManager` 拿玩家 Transform 和 BoundingBox 来算坐标和旋转角度，所以 **UI 不需要直接认识场景里的那些 MapRoot、角色 GameObject，只跟管理器打交道，耦合度比较低**。

### 综合起来就是：

世界里有个 Cube 当“量尺”，用它的 Collider.bounds 定义地图真实尺寸；场景初始化时把这把“量尺”交给 `MinimapManager`；UI 小地图通过 Manager 拿到 BoundingBox 和 PlayerTransform，把玩家的世界 XZ 坐标映射成 0~1 的 pivot，让大地图 Sprite 在 Mask 后面滑动；Mask 只是负责裁剪显示区域。整个方案就是一个“世界坐标 → 归一化 → UI pivot”的数学映射，再加一个全局 Manager 来解耦世界和 UI。
