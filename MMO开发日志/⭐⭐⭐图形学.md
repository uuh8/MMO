## 1. 你对“矩阵”和“线性变换”的理解是什么

- 矩阵可以看成一个**线性变换的表示**
- 这个线性变换如何作用，可以通过它**对一组基向量的作用**来完全确定
- 矩阵表示的是一个**线性变换**；而研究基矢量，是因为**线性变换只要知道它对基矢量做了什么，就知道它对整个空间做了什么**。

##### 回答：

**线性变换**描述的是一个空间到另一个空间的规则，它要求满足两件事：第一是保持向量加法，也就是 (T(a+b)=T(a)+T(b))；第二是保持数乘，也就是 (T(ka)=kT(a))。几何上，这意味着它可以做的事情包括旋转 `rotation`、缩放 `scale`、错切 `shear`、反射 `reflection`、投影 `projection` 这类操作，但不能直接表示普通意义下的平移，因为线性变换一定满足原点映射到原点。换句话说，线性变换本质上是在改变一个空间中的基和坐标表达方式，同时保持线性结构不被破坏。

**矩阵**本质上是线性变换在某组基下的一个具体表示。只要选定一组基，线性变换对每个基向量的作用就可以唯一确定这个变换，而这些“变换后的基向量坐标”排成列，就构成了这个矩阵。所以矩阵和线性变换的关系可以理解成：线性变换是几何对象，矩阵是它在坐标系中的代数表示。也正因为这样，矩阵乘法不是单纯的数值运算，它对应的是变换的复合；**矩阵可逆对应的是变换可逆**；行列式反映的是这个变换对**面积或体积的缩放**以及**是否发生了手性翻转**。

如果再结合图形学和游戏开发去理解，我会把矩阵看成是**“空间变换的编码方式”**。比如在 Unity 里，一个对象从 `local space` 到 `world space` 的变换，本质上就是矩阵在起作用；`worldToLocalMatrix` 则对应逆矩阵。从工程角度讲，我不会把矩阵只当成数学工具，而是把它看成连接几何空间、坐标系变换和渲染管线的核心中介。再往后扩展到 `homogeneous coordinates`，就可以把原本不是线性变换的平移，也统一纳入 `4x4 matrix` 的框架里，这样旋转、缩放、平移、投影都能用统一的矩阵乘法来组织，这也是图形学里矩阵如此核心的原因。



## 2. 什么是正交矩阵

正交矩阵本质上是**行向量或列向量构成标准正交基的矩阵**，也就是这些基向量**两两垂直且长度都为 1**。它满足 MMT=IMM^T=IMMT=I，因此它的**逆矩阵等于转置矩阵**。

几何上，正交矩阵表示保持**长度和夹角不变的线性变换**，所以它只可能表示**旋转或者反射**，不会包含缩放和错切。在图形学里它非常重要，因为旋转矩阵就是正交矩阵，很多空间变换的反向计算都可以**直接用转置代替求逆**，这在相机、物体朝向、TBN 基底和骨骼动画里都很常见。



## 3. 为什么图形学要用 4×4 矩阵

在三维图形中，3×3 矩阵只能表示线性变换，比如旋转、缩放和错切，不能表示平移；而通过引入齐次坐标，把三维点扩展成四维形式后，点可以写成 `(x,y,z,1)`，方向可以写成 `(x,y,z,0)`，这样**平移就能被统一写进 4×4 矩阵中**。对引擎来说，这种统一非常重要，因为物体从局部空间到世界空间、相机变换、父子节点层级、Shader 中的位置和方向处理，都依赖这种仿射矩阵表示。Unity 里的 `TransformPoint` 和 `TransformDirection` 之所以分开设计，本质上就是在区分 `w=1` 的点和 `w=0` 的方向。

**矩阵乘法只能表示线性变换**，真正被矩阵线性作用的是四维齐次空间；三维平移只是这个四维线性变换在 w=1w=1w=1 超平面上的表现。**把三维空间嵌入到四维齐次空间后，三维中的平移可以被实现为四维中的一种线性变换**；从几何效果上看，这个线性变换很像对三维超平面做了一次错切。结果是：**三维平移被提升成了四维中的线性操作**。

> 齐次坐标中的平移，本质上是四维空间里由 `w` 分量驱动的线性错切；因为真实三维点都落在 w=1 超平面上，所以这次高维错切在该超平面上表现为普通三维平移。



## 4. Unity中有什么与之对应的？

#### 场景 1：父子节点变换

子物体的局部坐标经过父节点 `localToWorldMatrix`，才能得到世界坐标。

这里本质上就是：

- 局部点 (x,y,z,1)，乘 4×4 仿射矩阵，得到世界点

如果父节点有 rotation + translation，那么子点就会先转再平移。

#### 场景 2：角色朝向和位移

角色的 `forward`、`right`、`up` 是方向，不该直接吃平移。而角色脚底某个挂点的位置，是点，应该吃平移。

这就是为什么“一个是轴向，一个是位置”在引擎里必须分开看。

#### 场景 3：摄像机

相机的世界变换也是一个 4×4 仿射矩阵。 `View Matrix` 本质上就是它的逆。

所以相机不是“特殊系统”，依然还是 6.4 的矩阵变换。

#### 场景 4：Shader

在 Shader 里特别典型：

```
float4 pos = float4(vertex.xyz, 1.0);
float4 dir = float4(normal.xyz, 0.0);
```

为什么这样写？因为：

- **顶点位置要吃平移**，所以 `w = 1`
- **法线/方向不该吃平移**，所以 `w = 0`

这就是 6.4 在图形管线里的直接落地。





## 5. 什么是透视投影？有什么作用？w不是只能是0和1吗？投射投影和w有什么关系？

<font color="#921a1a">透视投影的本质，是把三维空间中的点通过一个**投影中心 `Center of Projection`** 映射到二维投影平面上。</font>

它和正交投影最大的区别在于，正交投影的投影线彼此平行，而透视投影的投影线会汇聚到同一个投影中心，所以它会产生**近大远小**的视觉效果。从几何上看，针孔相机 `Pinhole Camera` 就是透视投影最经典的模型，投影公式本质来自相似三角形，例如如果投影平面在距离相机 `d` 的位置，那么点 (x,y,z)投影后横纵坐标会变成类似 (dx/z, dy/z)这样的形式，深度 z 越大，投影结果越小，这就是透视感的来源。

它的作用主要有两个层面。第一个层面是**视觉真实性**，因为人眼和真实相机看到世界时，本来就有透视缩短 `Perspective Foreshortening`，所以大多数 3D 游戏的主摄像机都会使用透视投影，这样场景空间感、纵深感、距离感都会更自然。第二个层面是**图形管线的统一表达**，因为渲染时我们需要把物体从对象空间一路变换到屏幕空间，透视投影负责**把三维视锥体里的点压到二维成像平面，并进一步进入 `clip space`、`NDC` 和屏幕坐标系统**，所以它是整个 `Model-View-Projection` 流程里不可缺的一步。

至于“`w` 不是只能是 0 和 1 吗”这个前提，其实是不准确的。**在仿射变换阶段**，我们通常为了区分“点”和“方向”，会把点写成 (x,y,z,1)，把方向写成 (x,y,z,0)。这里的 `w=1` 和 `w=0` 是一种很常用、很方便的输入约定，用来控制平移项是否生效：点应该被平移，方向不应该被平移。但是这并不意味着 `w` 永远只能取 0 或 1。到了**透视投影阶段**，**<font color="#921a1a">投影矩阵的一个核心任务，恰恰就是把将来要参与透视缩放的分母写进 `w` 里</font>**。也就是说，输入点通常是 (x,y,z,1)，但<font color="#921a1a">**经过投影矩阵之后，输出的 `clip coordinate` 往往会变成 (x′,y′,z′,w′)，这里的 `w'` 一般会和原来的深度 `z` 有关，而不再是 0 或 1**</font>。

所以透视投影和 `w` 的关系非常直接：**透视投影不是单靠矩阵乘法完成的，而是<font color="#921a1a">“投影矩阵 + 除以 w”</font>共同完成的。** 投影矩阵先把深度相关的信息编码到新的 `w` 分量里，然后 GPU 在后续阶段执行 `perspective divide`，也就是把 x,y,z 都除以 w。真正让物体出现近大远小效果的，不是单纯那次 4×4 矩阵乘法，而是后面的这一步除法。换句话说，**<font color="#921a1a">`w` 在仿射阶段主要承担“区分点和方向”的角色，而在透视投影阶段，它又承担了“透视除法分母”的角色</font>**，这就是齐次坐标在图形学里非常强大的地方。

如果再结合 Unity 或图形管线来讲，我会补充一句：Unity 里的 `Perspective Camera` 本质上就是在使用透视投影，`projectionMatrix` 会先把 view space 的点变到 clip space，其中 `w` 会被写成与深度有关的值，随后 GPU 自动完成除以 `w`，再映射到屏幕。所以面试里如果问到 `w`，我不会只回答“点是 1、向量是 0”，而会进一步指出：**那只是输入阶段的常见约定，在投影阶段 `w` 是会变化的，而且它正是透视投影成立的关键。**



## 6. Unity的世界变换

## Unity / Shader 里的完整路径

在 Shader 中最终常见到的是这条链：

```
Object→World→View→Clip
```

对应矩阵大致是：`Model`、`View`、`Projection`，组合成 `MVP`。然后 GPU 自动做：

- `clip -> NDC`：除以 `w`

所以如果问“透视到底在哪一步发生”，更准确的回答不是“在 Projection Matrix 那一步已经彻底完成了”，而是：

> **Projection Matrix 负责把透视信息编码进 clip space，真正完成透视缩放的是 clip 到 NDC 时的 divide by w。**



## 7. 第六章：矩阵详解 总结

如果把第六章从**游戏客户端 / Unity / Shader**的视角串成一条主线，我会把它理解成这样：**第六章本质上是在建立“现代图形学空间变换统一框架”的数学基础**。前面几章你学的是向量、点、坐标系、矩阵如何表示线性变换；而第六章进一步回答的是：这些矩阵表示的变换**能不能逆、是否保持结构、怎样把平移统一进去、怎样把透视投影也放进同一条矩阵管线**。如果站在 Unity 和 GPU 渲染流程上看，这一章其实就是在给 `Transform`、`localToWorldMatrix`、`worldToCameraMatrix`、`projectionMatrix`、`MVP`、`clip space`、`perspective divide` 这些概念补数学底层。

先说第六章的总体逻辑。它不是在教你更多零散公式，而是在把“空间变换”这件事越收越统一。6.1 的行列式，在游戏开发里不是一个单纯的代数量，而是在告诉你：一个矩阵对应的空间变换是否把空间压扁了、翻转了、放大或缩小了多少。几何上，二维里它是面积缩放倍数，三维里是体积缩放倍数；工程上，它直接关系到矩阵是否可逆，也关系到模型是否发生了手性翻转。比如在 Unity 里，如果某个对象做了 `scale = (-1,1,1)` 这种镜像缩放，那么对应变换的 `determinant` 就会是负的，这意味着空间 handedness 变了，实际表现上就可能引出三角形正反面、法线方向、`back-face culling` 异常这类渲染问题。再比如某个轴被缩放到 0，那么行列式就是 0，矩阵退化，逆矩阵不存在，这在骨骼、法线、空间来回变换里都会埋雷。所以 6.1 的真正价值，是让你从“矩阵有一堆数字”升级到“矩阵在操纵一个空间，而且这个空间可能被拉伸、压扁或翻转”。

接着 6.2 的逆矩阵，其实就是在讲**反向空间变换**。从游戏客户端角度看，这一节几乎等价于“为什么坐标系之间可以来回切换”。一个对象的 `localToWorldMatrix` 是把局部空间点送到世界空间，而 `worldToLocalMatrix` 就是在做逆矩阵；相机的世界变换矩阵如果表示的是相机在世界中的位置和朝向，那么 `View Matrix` 本质上就是它的逆；Shader 里从 object space 到 world space，到 view space，到 clip space，都是一路正向乘过去，而很多逻辑又需要逆回来，比如把世界方向转回局部、把局部法线转到世界、把骨骼绑定姿态逆回去，这背后都是逆矩阵。面试里如果问“逆矩阵的几何意义是什么”，不能只答 `MM^{-1}=I`，更应该答：**逆矩阵表示撤销原变换，把一个点从目标空间还原回源空间**。这一节和 Unity 的直接对应非常强，`TransformPoint` / `InverseTransformPoint`、`TransformDirection` / `InverseTransformDirection`、`localToWorldMatrix` / `worldToLocalMatrix`，本质上都是你刚学的逆矩阵在 API 层的具象化。

然后 6.3 的正交矩阵，是整个第六章里和图形学最直接绑定的一节，因为它几乎就是在讲**旋转矩阵的本质**。正交矩阵满足 `MM^T = I`，所以 `M^{-1}=M^T`。这条性质在游戏图形里重要到近乎“常识级底层规律”，因为<font color="#921a1a">**如果一个矩阵只表示纯旋转，或者旋转加反射，那么它的行或列就是一组标准正交基 `Orthonormal Basis`：彼此垂直、长度为 1**</font>。几何上这意味着它不会引入缩放和错切，只会改变方向；工程上这意味着你**不用做昂贵的一般求逆**，只要转置就能得到反向旋转。这背后最重要的图形学理解是：**旋转矩阵其实就是坐标轴本身**。比如某个物体的 `right / up / forward`，理想情况下就构成一组标准正交基；相机的朝向基底也是如此；`LookAt` 本质上也是在构造这样一组轴；TBN 空间里的 `Tangent / Bitangent / Normal` 理想情况下也应当是正交的。你把这节学透，后面看到“为什么 View Matrix 的旋转部分可以直接用转置”、“为什么相机局部坐标转世界坐标可以用基底组合，世界转相机坐标可以用点积投影”这些问题，就不会只会背结论了。

再往后 6.3.3 的正交化，不是纯数学附录，而是很工程化的一节。它回答的是：**如果一组本来应该作为坐标轴的向量，因为插值、浮点误差、外部输入或累积运算而不再严格正交了，怎么办**。这在游戏开发里非常常见。相机连续插值后，`forward/right/up` 可能会漂；骨骼矩阵多次累乘后，旋转部分可能混进一点缩放和剪切；法线贴图用到的 TBN 基底在插值后也经常不再严格正交，于是就会影响光照精度。**<font color="#921a1a">Gram-Schmidt 的几何本质不是背公式，而是“把后面的向量中沿着前面基向量的成分减掉，只留下垂直部分”</font>**，最后再做单位化，从而修复出一组新的标准正交基。工程上你要有这个意识：很多时候渲染 bug 不一定来自公式错了，而可能是**基底已经脏了**，需要重新正交化。

到了 6.4，主线开始发生一个关键升级：前面所有矩阵都在处理三维中的线性变换，而**平移不是线性变换**，因为线性变换必须满足原点映到原点。图形学之所以全面转向 `4×4 homogeneous matrix`，本质就是为了**<font color="#921a1a">把平移也纳入同一个矩阵系统</font>**。齐次坐标这件事如果从 Unity 角度理解，会非常自然：位置 `position` 是点，所以对应 `w=1`；方向、法线、速度这类量本质是方向或向量，不是位置，所以对应 `w=0`。这一下就解释了为什么 `TransformPoint` 要受 translation 影响，而 `TransformDirection` 不受 translation 影响；为什么 Shader 里顶点位置常写成 `float4(pos, 1.0)`，而方向、法线常写成 `float4(dir, 0.0)`。这不是 API 人为拆分类别，而是齐次坐标的数学本质决定的。更深一层理解是：在三维物理空间里，平移不能用 3×3 表示；但**<font color="#921a1a">当你把三维空间嵌入四维齐次空间后，三维中的平移可以表示成四维中的线性操作，所以图形管线才有可能把 rotation、scale、translation 统一成一个矩阵连续复合</font>**。

而 6.4 的 4×4 仿射矩阵，正是你理解 Unity `Transform` 的最佳数学抽象。Unity 编辑器里给你的是 `position + rotation + scale` 三个字段，但底层真正统一的表示，是一个**仿射变换矩阵**。它的左上角 3×3 是线性部分，可能包含 rotation、scale、甚至 shear；平移则落在最后一行或最后一列，取决于是行向量约定还是列向量约定。你这本书采用的是**行向量**约定，所以平移在最后一行，变换顺序也是从左到右读；而 Unity 生态里大量资料使用的是**列向量**思维，因此平移常放最后一列，复合顺序也是反过来理解。这个地方非常适合米哈游这类喜欢考底层的面试题，因为如果候选人只会背某个矩阵长相，却搞不清 row vector / column vector、左乘 / 右乘、空间变换先后顺序，就很容易被追问穿。你必须能明确说出：**矩阵排布长相不是本质，本质是约定；但一旦约定固定，平移位置、基向量排布、变换顺序都会跟着一起固定**。

6.4.3 的一般仿射变换，则是在告诉你：有了平移矩阵之后，原本第 5 章里那些默认“围绕原点”的线性变换，现在都可以推广到任意位置。图形学里围绕任意点旋转、围绕任意轴缩放、围绕不经过原点的平面做反射或投影，本质套路都是一样的：**<font color="#921a1a">先把中心搬到原点，做线性变换，再搬回去</font>**。这就是 `T R T^{-1}` 这类结构的意义。放到 Unity 里，这其实就是 **<font color="#921a1a">`pivot` 的数学本质</font>：为什么模型局部原点、子物体挂点、骨骼关节点的位置会直接影响物体绕哪旋转、在哪缩放，本质上就是你选择了一个不同的局部坐标系中心，从而改变了“先移到原点再变换再移回来”这一整套操作的中心**。很多 gameplay 程序员会把 pivot 问题只当编辑器经验，但图形学视角下它其实就是仿射变换中心变换的问题。

最后到 6.5，整章达到图形学意义上的真正闭环。6.4 解决的是“平移如何纳入矩阵”，而 6.5 解决的是“**透视投影这种带除法、不是普通三维线性变换的东西，为什么也能纳入矩阵管线**”。透视投影的几何本质是针孔相机 `Pinhole Camera`：所有投影线都汇聚到一个投影中心，所以物体离投影中心越远，投影越小，这就是近大远小。从公式看，透视投影核心是 `x' = dx / z`、`y' = dy / z` 这类关系，它不是普通三维线性变换，因为分母里出现了输入变量 `z`。齐次坐标在这里发挥了第二次关键作用：**投影矩阵并不直接完成透视，而是先把将来要用于透视缩放的分母编码进 `w`，随后在从 clip space 到 NDC 的阶段执行 divide by w，真正产生透视效果**。这句话你必须能说出来，因为它几乎是图形学面试中判断候选人是不是只会背 `MVP` 的分水岭。真正严谨的表述不是“Projection Matrix 完成了透视”，而是“Projection Matrix 把透视信息写进 clip coordinates，perspective divide 才真正完成近大远小”。

把这一节落到 Unity 和 Shader 上，你就能完整串起现代渲染管线。一个顶点在 Unity 里，先从 object space 经 `localToWorldMatrix` 到 world space，再经 `worldToCameraMatrix` 到 view space，再经 `projectionMatrix` 到 clip space；之后 GPU 自动做 `clip -> NDC` 的 divide by w，最后再映射到 viewport / screen。也就是说，Shader 里你最终看到的 `MVP`，本质上就是第六章所有内容的工程化收束：`Model` 依赖 6.4 的仿射矩阵，`View` 依赖 6.2 的逆矩阵和 6.3 的正交旋转，`Projection` 依赖 6.5 的齐次投影矩阵，而整个 `clip -> NDC` 又直接用到了 6.4/6.5 里对 `w` 的理解。你如果从这条线去答题，米哈游喜欢的那种“图形学数学本质 + Unity 工程映射 + GPU 管线实现”的考法，基本都能接住。

如果把第六章压成一条真正适合面试的主线，我会这样总结：**第六章本质上是在解决“如何用矩阵统一描述和分析游戏图形中的空间变换”这个问题。** 行列式告诉我们一个变换是否压缩、翻转或退化；逆矩阵告诉我们如何在空间之间反向切换；正交矩阵告诉我们为什么纯旋转的逆可以用转置高效表示；齐次坐标和 4×4 仿射矩阵把平移也纳入统一矩阵体系；最后透视投影矩阵再进一步把非线性的透视效果编码进 `w`，并通过 divide by w 完成投影。落到 Unity 和 Shader，这一整章最终对应的就是 `Transform`、`Matrix4x4`、`localToWorldMatrix`、`worldToLocalMatrix`、`worldToCameraMatrix`、`projectionMatrix`、`MVP`、`clip space`、`NDC`、`TransformPoint` 和 `TransformDirection` 这些核心概念。也就是说，这一章不是“数学课的附加知识”，而是整个客户端图形空间变换系统的底层骨架。
