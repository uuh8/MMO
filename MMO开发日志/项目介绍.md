## 🎮 项目简介：MMORPG 网络游戏开发项目

我正在独立开发一款多人在线角色扮演游戏（MMORPG），采用 **Unity 客户端 + .NET 服务端（Entity Framework + protobuf + SQL Server）** 的权威服务器架构。项目的目标是实现一个**从登录、角色创建、地图加载到实时同步战斗**的完整 MMO 流程。当前项目核心功能、架构及关键技术如下：

------

### 🧱 一、整体架构与技术栈

1. **客户端**：
   - 使用 **Unity + C#** 实现，负责渲染、UI交互、玩家输入、物理表现与动画控制。
   - 使用 **MonoBehaviour 单例模式** 管理系统模块（如 `GameObjectManager`、`CharacterManager`、`UIManager`、`SceneManager` 等）。
   - 网络通信基于 **protobuf 协议** 与自定义 `NetMessage` 封包结构，实现高效、二进制序列化的请求/响应。
   - 游戏逻辑严格分层为 **输入层（InputController）→ 逻辑层（Entity/Character）→ 表现层（EntityController/Rigidbody）**。
   - UI 系统采用 **UGUI + Canvas + 动态界面加载**；
   - 数据配置使用 **Excel → JSON(txt)** 流程，自动导出至客户端 `Resources/Data` 下，由 `DataManager` 统一加载并缓存。
2. **服务端**：
   - 基于 **.NET Framework / .NET Core + Entity Framework (EF)**，采用**权威服务器架构**：所有角色状态与逻辑更新由服务端计算。
   - 数据库使用 **SQL Server** 存储角色信息、地图状态、装备等；
   - 网络层通过 **protobuf** 定义消息结构；
   - 服务端主要模块包括：
     - `UserService`：处理登录/注册、角色创建与选择。
     - `MapManager` 与 `Map`：管理多地图实例与角色进入/离开。
     - `CharacterManager`：创建、维护、同步游戏中的角色对象。
     - `SessionManager`：维护网络连接、消息分发与心跳。
     - `DataManager`：加载服务器端的 JSON 配置表。
   - 权威逻辑：服务端每 tick 调用逻辑积分更新所有角色状态（移动、旋转、速度等）。
3. **共享库（Common DLL）**：
   - 存放客户端与服务器共用的定义：
     - 协议实体（`NCharacter`, `NEntity`, `NetMessage`）
     - 配置定义（`MapDefine`, `CharacterDefine`, `TeleporterDefine` 等）
     - 公共枚举与常量（`MapType`, `EntityType`, `Result`, `CharacterClass`）。
   - 保证双方在数据结构和逻辑层字段上的一致性。

------

### 🌍 二、世界与地图系统

- 所有地图信息（场景名、出生点、传送器、刷怪规则）来自 **配置表 (MapDefine/SpawnRuleDefine/TeleporterDefine)**。
- 服务端管理 `MapManager` 单例，负责加载配置、创建地图实例并在玩家进入时调用 `Map.CharacterEnter()`。
- 客户端根据服务器回包的 `mapId` 使用 `SceneManager.LoadScene()` 异步加载对应场景。
- 客户端场景初始化通过 `GameObjectManager` 创建所有角色 GameObject，并交由 `CharacterManager` 管理。
- 主城与战斗场景共享通用的场景加载逻辑与出生点管理。

------

### 🧍 三、角色系统（Entity / Character）

- 角色分为三种层级的实体：
  1. **TCharacter（数据库层）**：与 SQL 数据库表绑定，通过 EF 进行持久化存储；
  2. **Character（逻辑层）**：游戏运行时的角色逻辑对象（位置、速度、状态、动画状态机等）；
  3. **NCharacter（网络层）**：protobuf 消息对象，用于网络同步。
- 角色加载流程：
  - 客户端点击“开始游戏” → 发送 `UserGameEnterRequest`；
  - 服务端验证后调用 `MapManager.Instance[mapId].CharacterEnter()`；
  - 服务端广播 `MapCharacterEnterResponse`；
  - 客户端收到后：`CharacterManager.AddCharacter()` → `GameObjectManager.CreateCharacterObject()` → 实例化角色 → `MainPlayerCamera` 绑定；
  - 主角即可在画面中生成并受控。

------

### 🕹️ 四、输入控制与运动系统

- **输入层**：`PlayerInputController` 捕获按键输入（WASD、Space）；
- **逻辑层**：`Character` 对象维护逻辑坐标、方向、速度，使用 **逻辑积分**（`position += direction * speed * delta`）更新；
- **物理层**：`Rigidbody` 控制实际运动、碰撞与重力；
- **表现层**：`EntityController` 映射逻辑 → 世界坐标，驱动动画（Idle/Move/Jump），并对远端角色进行平滑插值；
- **相机系统**：`MainPlayerCamera` 每帧在 `LateUpdate()` 中跟随主角，防止抖动；
- **权威逻辑**：客户端负责本地预测；服务端权威计算位置并周期性广播状态更新。

------

### ⚙️ 五、配置表与数据管理系统

- 使用自制工具链：`Excel → JSON.txt → 拷贝至客户端/服务端 → DataManager 加载`；
- 公共定义结构存放于 **Common/Data**；
- 客户端有两个加载模式：
  - `Load()`：开发模式下同步加载；
  - `LoadData()`：在 LoadingManager 中异步协程分帧加载，防止卡顿；
- 服务端在启动时使用同步 `Load()`；
- 所有系统模块（地图、角色、刷怪、传送器）均通过 `DataManager` 提供的字典查表；
- 客户端使用 `Resloader.Load<TextAsset>("Data/xxx")` 从 `Resources` 读取配置。

------

### 📡 六、网络通信与消息分发

- 采用自定义消息封包结构 `NetMessage`，支持长度头 + 序列化体；
- 协议定义使用 **protobuf (.proto)** 自动生成 C# 类；
- 服务端使用 `MessageDistributer` 分发不同类型的消息（登录、地图、角色、物品等）；
- 客户端通过 `NetClient` 封装异步接收与发送；
- 支持 `Request/Response` 与广播型 `Notify`；
- 为降低开销，关键同步包使用**压缩坐标 + 枚举映射 + 状态差量更新**。

------

### 💾 七、数据库与持久化层

- 服务端使用 **Entity Framework (EF)** 连接 SQL Server；
- `TCharacter`, `TUser`, `TItem` 等实体映射至数据库表；
- 玩家登录时从 DB 加载角色数据；
- 登出或服务器 Tick 定期自动持久化角色状态；
- EF 上层封装了 `UserService`、`CharacterService`、`MapService` 等逻辑层 API。

------

### 🧰 八、资源加载与工具链

- 资源加载由 `Resloader` 封装 `Resources.Load<T>()`；
- 支持加载：
  - 文本资源（配置 JSON）
  - 预制体（角色、UI、地图对象）
  - 精灵、音效、材质等；
