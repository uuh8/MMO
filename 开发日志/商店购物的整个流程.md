## 商店购买物品到背包的整个流程

这个操作整个流程会涉及到4个系统，分别是：npc系统、道具系统、背包系统、商店系统。

入口是npc，首先 `NPCDefine`如下：

```c#
public class NpcDefine
{
    public enum NpcType
    {
        None,
        Functional,
        Task
    }
    public enum NpcFunction
    {
        None,
        InvokeShop,
        InvokeInsrance
    }
    public int ID { get; set; }
    public string Name { get; set; }
    public string Descript { get; set; }
    public NVector3 Position { get; set; }
    public NpcType Type { get; set; }
    public NpcFunction Function { get; set; }
    public int Param { get; set; }
}
```

------

#### 客户端

1. 我点击商店npc后，会触发 `NpcController`，其中通过OnMouseDown可以识别到鼠标点击到npc，触发其中的协程StartCoroutine(DoInteractice())，（解释这儿协程的作用），通过协程进入NPCManager中的Interactive()。Interactive()会识别该npc是任务npc还是道具npc，该功能需要的是道具npc，触发`DoFunctionInteractive`方法，`DoFunctionInteractive`最终会返回 `return eventMap[npc.Function](npc);`，这句话相当于委托的触发。
2. NPCManager中维护了一个委托和一个字典如下

```c#
public delegate bool NpcActionHandler(NpcDefine npc);

Dictionary<NpcFunction, NpcActionHandler> eventMap = new Dictionary<NpcFunction, NpcActionHandler>();
```

此外还有一个注册函数`public void RegisterNpcEvent(NpcFunction function, NpcActionHandler action)`，在 `ShopManager.Init()`中，会调用这个注册函数，在NPCDefine中，枚举值NpcFunction.InvokeShop就是专门用于npc唤醒商店页面的，因此传入注册函数的参数，另一个参数用ShopManager中定义的OnOpenShop()函数，将其加入NPCManager的委托当中，OnOpenShop中会通过DataManager来校验商店是否存在和有效，然后通过UI框架的 `UIShop uiShop = UIManager.Instance.Show<UIShop>();` 在UI层面显示出商店的外观。 

> “打开商店”客户端这一功能涉及到的脚本文件有：`NpcDefine`,`NpcController`,`NPCManager`,`ShopManager`,`UIShop`,`UIManager`

------

1. 现在商店的UI已经打开了，每个ShopItem都挂载了两个组件：`UIShopItem`和 `Selectable`，使用`Selectable`组件，我们需要在`UIShopItem`下实现`ISelectHandler`接口，也就是要实现其中唯一的 `void OnSelect(BaseEventData eventData)` 方法，当我们选中一个物品后，会触发OnSelect方法，其中会执行 `this.shop.SelectShopItem(this);` 这句代码会执行 `UIShop`中的 `SelectShopItem` 方法，其中会将这个UIShopItem传递给 `UIShop`中的一个私有字段 `selectedItem`，这个私有字段在后续点击”购买“按钮后，会被传递给`OnClickBuy()`函数，进而被传递给 `ShopManager.Instance.BuyItem(this.shop.ID, this.selectedItem.ShopItemID)`。在 `ShopManager.Instance.BuyItem`中，`shop.ID`和`selectedItem.ShopItemID`，又会进一步的传递给 ` ItemService.Instance.SendBuyItem(shopId, shopItemId)`，

2. SendBuyItem会构造 `ItemBuyRequest`请求，将`shopId`和`shopItemId`发送给服务端，至此客户端一阶段的工作完成

   > "点击购买"客户端这一功能涉及到的脚本文件有：`UIShopItem`,`UIShop`,`ShopManager`,`ItemService`

------

#### 服务端

1. 客户端的`ItemService` 接收到 `ItemBuyRequest` ，响应函数 `OnItemBuy` 中会调用 `var result = ShopManager.Instance.BuyItem(sender, request.shopId, request.shopItemId);` 将得到的这个Result用于构造 `ItemBuyResponse`网络消息发送回客户端。

2. 其中`ShopManager.Instance.BuyItem(sender, request.shopId, request.shopItemId);` 中，会通过DataManager来验证商店ID和商店物品ID合不合法，以及金币是否足够，来判断本次购买是否成功，将成功与否通过我们在proto文件中定义的RESULT来传递回客户端。

   ```protobuf
   enum RESULT
   {
   	SUCCESS = 0;
   	FAILED = 1;
   }
   ```

   如果校验没问题，金币也足够，就会进入 `ShopManager.BuyItem`中真正“买”的逻辑，也就是下面这三行

   ```c#
   sender.Session.Character.ItemManager.AddItem(shopItem.ItemID, shopItem.Count);
   sender.Session.Character.Gold -= shopItem.Price;
   DBService.Instance.Save();
   ```

3. `ItemManager` 中维护了一个字典 `Items`用于管理角色身上的所有道具，购买成功后调用的 `AddItem` ，其中首先会验证该道具玩家是否已持有，如果已持有，直接数量增加，否则就需要在`TCharacterItem dbItem = new TCharacterItem()`数据表中插入一条新数据，然后添加到 `Itmes`字典中

4. 由于要返回给客户端的内容涉及多个方面，老师给出做法是在proto中定义**“状态”变量**，

   ```protobuf
   // 动作类型
   enum STATUS_ACTION
   {
   	UPDATE = 0;	// 不涉及数值的变化，例如仅“状态”的更新
   	ADD = 1;	// 增加
   	DELETE = 2;	// 删除
   }
   // 状态变化的种类
   enum STATUS_TYPE
   {
   	MONEY = 0;
   	EXP = 1;
   	SKILL_POINT = 2;
   	ITEM = 3;
   }
   // 用一个通用的“状态结构”，可以代表游戏中所有可能的状态变化，这样就可以避免返回多次不同的响应
   message NStatus
   {
   	STATUS_TYPE type = 1;
   	STATUS_ACTION action = 2;
   	int32 id = 3;
   	int32 value = 4;
   }
   // 一个状态通知数组，实际在网络中传输的message，因为是数组，所以可以传递多种状态变化，避免了多次不同协议的通知发送
   message StatusNotify{
   	// 用数组表示状态列表，可以一次传递多次变化
   	repeated NStatus status = 1;
   }
   ```

   此外，在`NetSession`中添加一个 `private NetMessage response;`，目的是不再把response放在每个“方法周期”里，而是放在每个“会话周期”里，相当于每个会话周期的全局response，这样就可以在不同过程随时向response中添加信息，最后一次性Send到客户端。`NetSession`中实现的`INetSession`接口会实现GetResponse方法，该方法实现如下，主要目的是保证response一定在会话session一开始创建，会话session结束清空。

   ```C#
           public byte[] GetResponse()
           {
               if(response != null)
               {
                   // 状态有变化（HasStatus），才加入进去
                   if(this.Character != null && this.Character.StatusManager.HasStatus)
                   {
                       this.Character.StatusManager.ApplyResponse(Response); 
                   }
                   byte[] data = PackageHandler.PackMessage(response);
                   // 只要消息发送给客户端，就清空这个response消息，这样就保证了response一定是在会话session一开始创建，会话session一结束清空；并且我们可以在会话session期间对response多次赋值让其包含多个消息
                   response = null; 
                   return data;
               }
               return null;
           }
   ```

   此外创建了一个 `StatusManager`，在`Character`实体类中和角色一同初始化 ` this.StatusManager = new StatusManager(this);`，相当于绑定角色。其中用一个列表Status来管理状态 `private List<NStatus> Status { get; set; }`，

5. 现在我们再回看 `ItemService`中的 `OnItemBuy`中下面这三步：

   ```c#
               sender.Session.Response.itemBuy = new ItemBuyResponse();
               sender.Session.Response.itemBuy.Result = result;
               sender.SendResponse();
   ```

   在SendResponse()之前，由于Response有状态变化，会被`GetResponse()`捕获到，然后通过 `ApplyResponse`把状态的变化加到 `statusNotify`这个网络消息中，最后一次性通过`SendResponse()`发回客户端。

   > 服务端处理响应这一过程涉及到的脚本文件有：`ItemService`,`ShopManager`,`ShopItemDefine`,`ItemManager`,`DBService`,`Item`,`NetSession`,`StatusManager`

#### 客户端

1. 客户端创建了一个 `StatusService`，和NPC系统类似，也维护了一个委托和一个字典，以及一个注册函数 `RegisterStatusNofity` 如下

   ```c#
           public delegate bool StatusNotifyHandler(NStatus status);
   
           Dictionary<StatusType, StatusNotifyHandler> eventMap = new Dictionary<StatusType, StatusNotifyHandler>();
   
           public void RegisterStatusNofity(StatusType function, StatusNotifyHandler action)
           {
               if (!eventMap.ContainsKey(function))
               {
                   eventMap[function] = action;
               }
               else
               {
                   eventMap[function] += action;
               }
           }
   ```

   还会监听服务端发来的状态网络协议 `StatusNotify`，并设置响应函数 `OnStatusNotify`，主要行为就是遍历其中的Status，然后根据不同的 `status.Actioin`来执行不同的逻辑，

2. `ItemManager`会调用注册函数`RegisterStatusNofity`注册通知，

   > 客户端处理响应这一过程涉及到的脚本文件有：
   >
   > `StatusService`,`ItemManager`,`BagManager`
